## Security review findings

The implementation covers URL scheme and length validation, database-backed analytics, bounded referrer persistence, and self-link rejection. Remaining risks include analytics/code enumeration without rate limiting, invalid analytics codes still reaching service-layer logs and audit data, and a request-Host fallback that contradicts the configured-origin requirement but is an explicitly accepted risk.

| Severity | File | Issue | Recommendation | Disposition |

## Remaining risks

- severity: MEDIUM; summary: When app.public-origin is explicitly empty, ShortUrlBuilder retains a legacy branch that derives shortUrl from the incoming request host.; impact: A host-header-controlled generated URL remains possible in that configuration and does not fully satisfy the configuration-only fallback requirement.; status: Accepted by human decision; mitigation: Require a non-empty APP_PUBLIC_ORIGIN in deployments; a future hardening change should remove the legacyRequestOrigin branch and construct fallback URLs solely from trusted server configuration.
- severity: MEDIUM; summary: The analytics endpoint and existing code-resolution endpoints remain unauthenticated and rate-limited only by deployment infrastructure, if any.; impact: Code probing, analytics enumeration, and request abuse remain possible.; mitigation: Apply per-client and/or per-code rate limiting at the reverse proxy or API gateway and monitor repeated invalid analytics requests.
- severity: LOW; summary: Redirect event persistence adds database work to every successful redirect and failures prevent a successful redirect.; impact: Redirect latency and availability now depend on event and audit persistence.; mitigation: This is the documented transactional trade-off required to prevent a successful redirect without its event; monitor persistence failures and event-table indexes.

## Trade-offs

- choice: Persist eventDay alongside precise eventTime.; benefit: Database grouping is deterministic across H2 and production timezone behavior.; cost: Calendar-day data is tied to the configured timezone at event creation and requires an additional persisted column.
- choice: Truncate oversized Referer headers rather than reject redirects.; benefit: A maliciously large header cannot make an otherwise valid redirect fail.; cost: Analytics may contain an intentionally truncated referrer value.
- choice: Keep the legacy request-origin fallback when app.public-origin is empty.; benefit: Preserves released shortUrl behavior under the human-approved compatibility decision.; cost: The fallback is not fully protected from Host-header influence.
